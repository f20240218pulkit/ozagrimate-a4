# Team workflow

1. Clone the repository and create a branch for your work, such as `aditya/telemetry`, `thomas/irrigation` or `bradley/alerts`.
2. Keep changes within your allocated work and coordinate any shared contract changes before implementation.
3. Include your API documentation and Postman requests with the code. Verify successful responses and relevant errors.
4. Open a pull request for review before merging. Do not force-push main.
5. Match service/component names across ADRs, diagrams, documentation and code. State which target features remain unimplemented.

The initial repository contains only Pulkit's completed implementation and proposed design contribution. A folder name or a proposed diagram is not evidence of a working service.

Never commit real credentials, .env files or screenshots containing browser/account information. The original Postman screenshot is retained in Pulkit's project evidence; a results summary is committed here.
